# KlinikForm SIMRS

Clinical intake and electronic medical record system for a Indonesian hospital,
built to the specification in [`docs/`](docs/). Server-rendered Laravel and
Alpine, a versioned JSON form engine, AES-256-GCM field encryption, SatuSehat
FHIR R4 and BPJS VClaim gateways, and an immutable Permenkes No. 24/2022
audit trail.

## Quick start

```bash
cp .env.example .env
docker compose -f docker/compose.yaml up -d
docker compose -f docker/compose.yaml run --rm app php artisan key:generate
docker compose -f docker/compose.yaml run --rm app php artisan migrate --seed
npm install && npm run build
```

The portal is on `http://127.0.0.1:8080` (nginx) or `http://127.0.0.1:8000`
(PHP built-in server). Both proxy the same application.

Three values in `.env` have no safe default and must be set before any real
data exists:

| Variable | Purpose |
| :--- | :--- |
| `APP_KEY` | AES-256-GCM data key. Rotating it without `klinikform:rotate-keys` makes every encrypted column unreadable. |
| `BLIND_INDEX_PEPPER` | HMAC pepper for the deterministic NIK lookup hash. Changing it orphans every patient's `nik_hash`. |
| `FAPI_TOKEN` | Static bearer token for the interoperability gateways. |

## Architecture in one page

- **Forms are data.** A form is a versioned JSON document in `form_templates`.
  The nurse's page is rendered from the active version; a submission is
  validated against the exact version it was captured under, so publishing a
  new version never changes an existing record. See
  [`docs/architecture.md`](docs/architecture.md).
- **Clinical values are recomputed, not trusted.** The GCS widget shows a
  total in the browser and the server derives it again from E/V/M before
  storing. Every calculator has a server-side twin under
  `app/Services/Clinical/`.
- **Sensitive fields are encrypted, and the schema decides which.** Anything
  marked `"confidential": true` is lifted out of `payload_data` and written to
  an AES-256-GCM column instead. NIK is additionally blind-indexed so it can
  be searched for without being stored in clear.
- **Sign-off is irreversible.** A signed submission gets a SHA-256 hash over
  its payload, diagnosis and signer. The database refuses to update or delete
  a locked row, and the audit log is append-only at the trigger level, not
  just by convention.
- **The audit trail is the product.** Permenkes 24/2022 compliance is the
  reason this system exists; the PDF export and the immutable store are
  built for that, not for debugging.

## Tests

```bash
# PHP unit + feature, with coverage against the >=90% target in docs/testing.md
docker compose -f docker/compose.yaml run --rm app \
  vendor/bin/pest --testsuite=Unit,Feature --coverage --min=90

# Browser end-to-end. Needs chromedriver on :9515.
docker compose -f docker/compose.yaml run --rm dusk sh -c \
  'chromedriver --port=9515 >/tmp/cd.log 2>&1 & sleep 3; php artisan dusk'

# Static analysis and style
docker compose -f docker/compose.yaml run --rm app vendor/bin/phpstan analyse --no-progress
docker compose -f docker/compose.yaml run --rm app vendor/bin/pint --test
```

The `Browser` suite is excluded from the default Pest run on purpose: it needs
a browser and a served application. CI runs it as a separate job.

Load profiles for the NFR-03 latency targets live in `tests/Performance/`.

## Deploying it (free)

Two accounts, no credit card, about an hour.

**1. Database — [Neon](https://console.neon.tech), free plan with no expiry.**

Render's own free Postgres is deleted 30 days after creation, which would take
a portfolio link down with it. Neon does not expire. Create a project and copy
its connection string.

**2. Web service — Render, free web service.**

Render → New → Blueprint → pick this repository. The [`render.yaml`](render.yaml)
in the repo fills in everything except two values it cannot know:

| You supply | Where it comes from |
| :--- | :--- |
| `APP_URL` | Render fills it in once the service has a URL |
| `DB_URL` | The Neon connection string, which already ends in `?sslmode=require` |

The three secrets are generated by the blueprint. Seed the demo data once from
Render's shell:

```bash
php artisan db:seed
```

**Keep it awake.** Render's free tier sleeps a service after 15 idle minutes
and takes about a minute to wake. A free cron (cron-job.org hitting `/up`
every 14 minutes) stays inside the 750 instance-hours included in the plan and
keeps the first visitor from waiting.

### What the demo is and is not

- The seeded personas share the password `password`. That is deliberate for a
  demo and wrong for anything else.
- Performance figures in [`docs/testing.md`](docs/testing.md) were measured on
  a 12 vCPU machine. The free tier gives 0.1 vCPU, roughly 120× less, so the
  demo is slower than the numbers claim. The numbers are the honest ones from
  a real test run, not from the host it is served on.
- Redis is not used here. The `cache`, `sessions` and `jobs` tables already
  exist, so all three run on the database.

### Running the full production image locally

The deploy target is the same code path the PaaS host runs:

```bash
docker build -f docker/Dockerfile --target deploy -t klinikform-simrs:deploy .
```

See [`docs/deployment.md`](docs/deployment.md) for the VPS path and the
container layout.

## Operations

- **Key rotation**: `php artisan klinikform:rotate-keys`. Re-encrypts every
  `EncryptedGcm` column under a new `APP_KEY` and retires the previous one.
  Take a database backup first; the command is not transactional across all
  tables.
- **Queue worker**: `QUEUE_CONNECTION=redis`, and
  `php artisan queue:work` must be running for the SatuSehat sync. Without it
  encounters sit at `satusehat_sync_status = PENDING` until a worker picks
  them up.
- **Webhook secrets** are generated server-side and shown once at
  registration. They are not recoverable afterwards — rotate by deleting and
  re-registering the endpoint.
- **Failed SatuSehat syncs** retry three times (10 s / 30 s / 60 s) and are
  then flagged `FAILED` for Rekam Medis to resolve. They are never retried
  indefinitely.

See [`docs/deployment.md`](docs/deployment.md) for the full runbook.
